## 1. esbuild 基础知识

### 1.1 什么是 esbuild

esbuild 是一个使用 **Go 语言**编写的**极速打包工具**，旨在提升现代 Web 开发的构建性能 。它不仅仅是一个打包器，也提供了代码转换（transpilation）和压缩（minification）等功能。

它的主要功能包括：

- **将多个文件打包**：将 JavaScript、TypeScript、JSX、CSS 以及其它资源文件打包成浏览器或 Node.js 可运行的文件 。
- **代码转换**：将较新的 JavaScript/TypeScript/JSX 语法转换为兼容性更好的旧版本。
- **Tree Shaking**：自动移除未使用的代码，减小最终包的体积。
- **代码压缩（Minify）**：移除不必要的空格、缩短变量名等，进一步减小文件大小。
- **生成 Source Map**：帮助开发者在浏览器调试时定位到原始源代码。
- **内置多种内容类型支持**：原生支持 JS、TS、JSX、CSS、JSON 等 。
- **本地开发服务器和监听模式**：方便开发时快速预览和调试。
- **插件系统**：通过插件扩展其功能 。

#### 为什么这么快？

1.  **Go 语言优势**：Go 是编译型语言，执行效率远高于 Node.js（通常由 JavaScript 编写）。
2.  **并行处理**：充分利用多核 CPU 进行并行编译和处理。
3.  **高效的算法和数据结构**：内部使用了优化的解析器、链接器和压缩器。
4.  **一次解析，多次输出**：内部共享解析结果，避免重复工作。

---

### 1.2 核心优势

| 特性            | 解释                                                          | 使用场景                                                          |
| --------------- | ------------------------------------------------------------- | ----------------------------------------------------------------- |
| 极速构建        | 比 Webpack/Rollup 快 10-100 倍 。                             | 大型前端项目、持续集成/持续部署 (CI/CD)、需要快速反馈的开发环境。 |
| 零配置/开箱即用 | 大部分现代前端技术（JS, TS, JSX, CSS）无需额外配置即可使用 。 | 快速原型开发、小型项目、不想花时间在配置上的团队。                |
| 多格式支持      | 原生支持 JavaScript、TypeScript、JSX、CSS 等 。               | 使用多种前端技术的项目。                                          |
| Tree Shaking    | 自动移除未使用的导出代码，有效减小打包体积 。                 | 所有项目，特别是使用大型库（如 Lodash）时。                       |
| 插件系统        | 提供插件 API，在构建过程的关键节点注入自定义逻辑 。           | 需要处理非标准文件类型（如 .md, .svg 内联）、自定义转换等。       |
| 易于集成        | 提供命令行、JavaScript API 和 Go API 。                       | 集成到现有构建流程、自定义构建脚本、构建工具开发。                |

## 2. esbuild CLI 入门

CLI（Command Line Interface）是使用 esbuild 最直接的方式，特别适合快速测试和小型项目。

### 2.1 安装

```bash
npm install --save-dev esbuild
# 或者全局安装 (不推荐，推荐项目本地安装)
# npm install -g esbuild
```

安装后，你可以在 `node_modules/.bin/` 目录下找到 `esbuild` 可执行文件，或者在 `package.json` 的 `scripts` 中直接使用 `esbuild` 命令。

---

### 2.2 基础打包

假设你的项目结构如下：

```
project-root/
├── src/
│   ├── index.js
│   └── utils.js
└── package.json
```

`src/utils.js`:

```javascript
// src/utils.js
export function sum(a, b) {
  return a + b;
}
```

`src/index.js`:

```javascript
// src/index.js
import { sum } from "./utils.js";
console.log(sum(1, 2));
```

在项目根目录下运行命令：

```bash
npx esbuild src/index.js --bundle --outfile=dist/bundle.js
```

#### 参数解析：

- `src/index.js`: 入口文件。
- `--bundle`: 告诉 esbuild 将入口文件及其所有依赖打包成一个文件。如果不加 `--bundle`，esbuild 只会转换单个文件。
- `--outfile=dist/bundle.js`: 指定打包后的输出文件路径和名称。如果目录不存在，esbuild 会尝试创建。

构建完成后，`dist/bundle.js` 将包含 `index.js` 和 `utils.js` 的合并代码。

---

### 2.3 常用参数

```bash
npx esbuild src/index.js \
  --bundle \
  --minify \
  --sourcemap \
  --target=es2017 \
  --format=iife \ # 默认对于浏览器是 iife
  --outfile=dist/bundle.js
```

#### 参数详解：

| 参数                  | 作用                                                                                                                 | 注意事项                                                          |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `--bundle`            | 打包入口文件及其依赖。                                                                                               | 必须指定才能进行打包。                                            |
| `--minify`            | 压缩输出的 JavaScript 和 CSS 代码，包括移除空格、缩短变量名等。                                                      | 生产环境构建时推荐开启。                                          |
| `--sourcemap`         | 生成 Source Map 文件 (`.map`)，便于在浏览器开发者工具中调试。                                                        | 开发环境建议开启，生产环境根据需要决定是否保留。                  |
| `--target=es2017`     | 指定输出的 JavaScript 语法版本。esbuild 会将代码转换为兼容该版本或更低版本的语法。                                   | 可以指定多个目标，如 `--target=es2017,chrome58,firefox57`。       |
| `--format=iife`       | 指定输出格式。常见选项：`iife` (立即执行函数表达式，适合浏览器)、`cjs` (CommonJS，适合 Node.js)、`esm` (ES Module)。 | 根据目标环境选择。                                                |
| `--outfile=path`      | 指定单个输出文件的路径。                                                                                             | 不能与 `--outdir` 同时使用。                                      |
| `--outdir=path`       | 指定输出目录。当有多个入口点时常用。                                                                                 | 不能与 `--outfile` 同时使用。                                     |
| `--loader:.ext=type`  | 为特定扩展名的文件指定加载器。例如 `--loader:.png=file`。                                                            | 用于处理非 JS/TS 文件，如 CSS、图片、文本等 。                    |
| `--define:NAME=value` | 在构建时替换全局标识符。例如 `--define:process.env.NODE_ENV=\"production\"`。                                        | 常用于注入环境变量或条件编译。                                    |
| `--external:module`   | 将指定模块标记为外部依赖，不打包进输出文件。                                                                         | 用于排除大型库（如 React），让其通过 CDN 或 `<script>` 标签引入。 |

---

### 2.4 输出多文件

当你有多个入口文件需要分别打包时，可以使用 `--outdir`：

```bash
npx esbuild src/page1.js src/page2.js --bundle --outdir=dist
```

这会将 `page1.js` 和 `page2.js` 分别打包到 `dist/page1.js` 和 `dist/page2.js`。

## 3. 适配前端技术栈

### 3.1 React / JSX

esbuild 原生支持 JSX 语法。对于 `.js` 文件中包含 JSX 的情况，需要显式指定加载器：

```bash
npx esbuild src/main.jsx --bundle --outfile=dist/app.js --loader:.js=jsx
# 或者直接处理 .jsx 文件 (通常无需额外 loader 指定)
npx esbuild src/main.jsx --bundle --outfile=dist/app.js
```

- `--loader:.js=jsx`: 告诉 esbuild `.js` 文件可能包含 JSX 语法并进行相应处理。

---

### 3.2 TypeScript

esbuild 原生支持 TypeScript 语法转换（`.ts`, `.tsx`）：

```bash
npx esbuild src/main.tsx --bundle --outfile=dist/app.js
```

> ⚠️ **重要提示**: esbuild **只进行语法转换**，**不执行类型检查**。你需要单独运行 TypeScript 编译器 (`tsc`) 来检查类型：

```bash
npx tsc --noEmit # --noEmit 表示只检查不输出文件
```

---

### 3.3 CSS

esbuild 可以处理 CSS 文件，并将其打包到 JavaScript 中（默认通过创建 `<style>` 标签注入）：

```bash
npx esbuild src/main.js --bundle --loader:.css=css --outfile=dist/app.js
```

或者直接打包 CSS 文件：

```bash
npx esbuild src/styles.css --bundle --outfile=dist/styles.out.css
```

- `--loader:.css=css`: 明确指定 `.css` 文件的加载器为 `css` 。

---

### 3.4 SCSS / Less

esbuild **不直接支持** SCSS 或 Less。你需要先使用对应的预处理器（如 `sass` 或 `less`）将它们编译成 CSS，然后再让 esbuild 处理生成的 CSS 文件。

安装 Sass:

```bash
npm install --save-dev sass
```

编译 SCSS:

```bash
npx sass src/style.scss dist/style.css
```

然后在 HTML 中引用 `dist/style.css`，或者作为入口点让 esbuild 打包它。

---

### 3.5 静态资源

使用 `--loader` 选项可以处理图片、文本等静态资源 ：

```bash
npx esbuild src/main.js \
  --bundle \
  --loader:.png=file \
  --loader:.svg=text \
  --loader:.json=json \
  --outfile=dist/app.js
```

- `.png=file`: 将图片文件复制到输出目录，并在代码中导入其 URL 路径（通常带有 hash）。
- `.svg=text`: 将 SVG 文件内容作为字符串导入。
- `.json=json`: 导入 JSON 文件并将其解析为 JavaScript 对象（这是默认行为）。

在 `src/main.js` 中使用：

```javascript
// 导入图片 URL
import logoPath from "./logo.png";
const img = document.createElement("img");
img.src = logoPath;
document.body.appendChild(img);

// 导入 SVG 字符串
import svgContent from "./icon.svg";
console.log(svgContent); // 输出 SVG 字符串

// 导入 JSON
import config from "./config.json";
console.log(config.appName);
```

## 4. 开发模式

### 4.1 Watch 模式

监听文件变化并自动重新构建：

```bash
npx esbuild src/main.js --bundle --outfile=dist/app.js --watch
```

当 `src/main.js` 或其依赖文件发生变化时，esbuild 会自动重新打包。

---

### 4.2 Serve 模式

esbuild 内置了一个简单的开发服务器：

```bash
npx esbuild src/main.js --bundle --outfile=dist/app.js --serve=8000 --sourcemap
```

这会启动一个 HTTP 服务器，监听在 `localhost:8000`。它会自动在浏览器中打开页面（如果支持），并提供构建后的文件。`--sourcemap` 对于调试很重要。

> ⚠️ **局限性**: 内置服务器功能相对简单，不支持 HTTPS、复杂的代理规则等。对于复杂需求，可以考虑配合 Nginx、Browsersync 或 Webpack Dev Server 使用。

---

### 4.3 自动刷新

结合外部工具（如 Browsersync）实现自动刷新：

首先安装 Browsersync:

```bash
npm install --save-dev browser-sync
```

然后运行两个命令（可以在不同的终端或使用 `concurrently` 等工具）：

```bash
# 终端1: 启动 esbuild watch 模式
npx esbuild src/main.js --bundle --outfile=dist/app.js --watch

# 终端2: 启动 Browsersync
npx browser-sync start --server 'dist' --files 'dist'
```

或者使用 `concurrently`:

```bash
npm install --save-dev concurrently
```

在 `package.json` 中添加脚本：

```json
{
  "scripts": {
    "dev": "concurrently \"npx esbuild src/main.js --bundle --outfile=dist/app.js --watch\" \"npx browser-sync start --server 'dist' --files 'dist'\""
  }
}
```

运行 `npm run dev` 即可同时启动构建监听和自动刷新服务器。

## 5. JavaScript API 构建

使用 JavaScript API 可以实现更复杂和灵活的构建配置。这对于构建脚本、集成到其他工具或需要条件逻辑的场景非常有用 。

### 5.1 基本构建脚本

创建一个 `build.js` 文件：

```javascript
// build.js
import { build } from "esbuild";
import process from "process"; // 用于处理退出码

const isProduction = process.env.NODE_ENV === "production";

build({
  entryPoints: ["src/main.tsx"], // 入口点
  bundle: true, // 打包
  outfile: "dist/app.js", // 输出文件
  minify: isProduction, // 生产环境压缩
  sourcemap: !isProduction, // 开发环境生成 source map
  target: ["es2020"], // 目标环境
  loader: {
    ".png": "file", // 图片加载器
    ".svg": "text", // SVG 加载器
  },
  define: {
    "process.env.NODE_ENV": JSON.stringify(
      process.env.NODE_ENV || "development"
    ), // 定义环境变量
  },
}).catch((error) => {
  console.error("Build failed:", error);
  process.exit(1); // 构建失败时退出码设为 1
});
```

运行脚本：

```bash
# 开发环境
NODE_ENV=development node build.js

# 生产环境 (Unix/Linux/macOS)
NODE_ENV=production node build.js

# 生产环境 (Windows PowerShell)
$env:NODE_ENV="production"; node build.js

# 生产环境 (Windows CMD)
set NODE_ENV=production && node build.js
```

---

### 5.2 多入口与代码分割

```javascript
// build.js
import { build } from "esbuild";

build({
  entryPoints: ["src/index.js", "src/admin.js"], // 多个入口点
  outdir: "dist", // 输出目录
  bundle: true,
  splitting: true, // 开启代码分割
  format: "esm", // 代码分割需要 ESM 格式
  minify: true,
  sourcemap: true,
}).catch(() => process.exit(1));
```

这会为 `index.js` 和 `admin.js` 生成独立的 bundle，并将它们共享的代码提取到单独的 chunk 文件中。

## 6. 插件系统

### 6.1 插件原理

esbuild 插件允许你在构建过程的关键阶段（如解析模块路径、加载文件内容）注入自定义逻辑 。插件通过 `onResolve`（解析路径）和 `onLoad`（加载文件内容）这两个核心钩子来工作 。

> ⚠️ **重要**: 插件 API **只能通过 JavaScript 或 Go API 使用**，**不能在命令行中直接使用** 。

### 6.2 插件示例：Markdown Loader

创建一个简单的插件，将 `.md` 文件作为字符串导入：

```javascript
// markdownPlugin.js
import fs from "fs/promises";

export const markdownPlugin = {
  name: "markdown-loader", // 插件名称
  setup(build) {
    // onLoad 钩子：当 esbuild 需要加载匹配 filter 的文件时触发
    build.onLoad({ filter: /\.md$/ }, async (args) => {
      // args.path 是文件的绝对路径
      console.log(`Loading Markdown file: ${args.path}`);
      try {
        const text = await fs.readFile(args.path, "utf8");
        // 返回内容，esbuild 会将其作为模块导出
        // 这里简单地将内容 JSON.stringify 后作为默认导出
        return {
          contents: `export default ${JSON.stringify(text)};`,
          loader: "js", // 指定返回内容的 loader
        };
      } catch (err) {
        return { errors: [{ text: `Failed to read file: ${err.message}` }] };
      }
    });
  },
};
```

### 6.3 使用插件

修改 `build.js` 来使用这个插件：

```javascript
// build.js
import { build } from "esbuild";
import { markdownPlugin } from "./markdownPlugin.js"; // 导入插件

build({
  entryPoints: ["src/main.js"],
  bundle: true,
  outfile: "dist/app.js",
  plugins: [markdownPlugin], // 注册插件
}).catch(() => process.exit(1));
```

在 `src/main.js` 中使用：

```javascript
// src/main.js
import readmeContent from "./README.md";

console.log(readmeContent); // 输出 README.md 的内容
```

## 7. 高级优化

### 7.1 代码分割

代码分割是优化大型应用加载性能的关键技术。esbuild 通过 `splitting` 选项支持动态导入和多入口点的共享代码提取 。

```javascript
// build.js
import { build } from "esbuild";

build({
  entryPoints: {
    app: "./src/app.js",
    admin: "./src/admin.js",
  },
  outdir: "dist",
  bundle: true,
  splitting: true, // 启用代码分割
  format: "esm", // 必须是 ESM 格式
  minify: true,
  sourcemap: true,
}).catch(() => process.exit(1));
```

在代码中使用动态导入：

```javascript
// src/app.js
async function loadFeature() {
  const { heavyFunction } = await import("./heavyFeature.js");
  heavyFunction();
}
```

esbuild 会自动将 `heavyFeature.js` 及其依赖打包成一个独立的 chunk，并在需要时按需加载。

---

### 7.2 Tree Shaking

Tree Shaking 依赖于 ES Module (ESM) 的静态结构。确保你的库和代码使用 `import`/`export` 语法，esbuild 会自动进行未使用代码的删除。

- **对 ESM 模块效果最好**。
- **CommonJS 模块**可能无法完全移除未使用代码，因为其导入/导出是动态的。

---

### 7.3 生产构建

生产构建通常需要启用所有优化选项：

```javascript
// build.prod.js
import { build } from "esbuild";

build({
  entryPoints: ["src/main.js"],
  bundle: true,
  minify: true, // 压缩代码
  sourcemap: false, // 生产环境通常不保留 source map
  target: ["es2017"], // 根据目标浏览器设定
  outfile: "dist/app.js",
  define: {
    "process.env.NODE_ENV": JSON.stringify("production"), // 注入生产环境变量
  },
  // 可以添加其他生产优化，如 metafile 用于分析
  metafile: true, // 生成元数据文件，用于分析 bundle 构成
})
  .then((result) => {
    // 可选：将 metafile 写入文件供分析工具使用
    // require('fs').writeFileSync('meta.json', JSON.stringify(result.metafile))
    console.log("Production build completed.");
  })
  .catch(() => process.exit(1));
```

## 8. 生产部署

### 8.1 CI/CD 示例（GitHub Actions）

`.github/workflows/build.yml`:

```yaml
name: Build and Deploy

on:
  push:
    branches: [main] # 或你的默认分支
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest

    strategy:
      matrix:
        node-version: [18.x] # 选择你需要的 Node.js 版本

    steps:
      - uses: actions/checkout@v3

      - name: Use Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v3
        with:
          node-version: ${{ matrix.node-version }}

      - name: Install dependencies
        run: npm ci # 使用 ci 保证依赖一致性

      - name: Run type check (if using TypeScript)
        run: npx tsc --noEmit # 只检查类型

      - name: Build project
        run: NODE_ENV=production node build.prod.js # 运行生产构建脚本

      - name: Upload build artifacts
        uses: actions/upload-artifact@v3
        with:
          name: dist
          path: dist/ # 上传构建产物


    # 这里可以添加部署步骤，例如推送到服务器、部署到 CDN、触发 Netlify/Vercel 构建等
    # - name: Deploy to Server
    #   # ... 部署命令 ...
```

### 8.2 老浏览器兼容

esbuild 可以将代码转换为目标浏览器兼容的语法。对于需要 Polyfill 的 API（如 `Promise`, `fetch`），esbuild 本身不处理，需要借助 Babel 或其他工具。

1. **使用 esbuild 转换语法**:

```bash
npx esbuild src/main.js --bundle --target=es2015 --outfile=dist/legacy.js
```

2. **使用 Babel 添加 Polyfill** (示例):

```bash
npm install --save-dev @babel/core @babel/cli @babel/preset-env core-js
```

`.babelrc`:

```json
{
  "presets": [
    [
      "@babel/preset-env",
      {
        "useBuiltIns": "usage",
        "corejs": "3"
      }
    ]
  ]
}
```

运行 Babel:

```bash
npx babel dist/legacy.js --out-file dist/legacy.polyfilled.js
```

现在 `dist/legacy.polyfilled.js` 应该能在更老的浏览器中运行了。
